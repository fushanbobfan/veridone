# Changelog

All notable changes are documented here. This project follows Semantic Versioning.

## [Unreleased]

### Added

- `pnpm walk:first-workspace`, `pnpm walk:upgrade`, and `pnpm walk:dead-ends` rerun the release walks from a clone, and `pnpm walk:release` runs the local gates and the walks at one commit. The **Release walks** workflow runs the walks on Ubuntu, Windows, and macOS after each merge and every Monday.
- **Remove** takes an approved or restored root, a repository, or a work item out of the workspace with a reason, and **Removed** in the navigation lists each one and puts it back. A removed repository's work items stay in the inbox on its last captured state, with acceptance locked, and can move to another repository or be decided as they can when a repository cannot be read. Verdict and evidence rows do not change, packets state the removal of their work item and its repository, backups carry a removal, and a restore neither removes a local record nor undoes a local removal. Migration 15 adds the state; `schemaVersion` 2 backups and packets gain fields that older backups can leave out, so those still restore. `pnpm walk:removal` walks it in the built app, on a workspace and a backup from the real v1.2.0 build.

### Changed

- A repository capture starts fewer processes, so the bootstrap that every page load of the local app and its 15-second refresh run is faster with many repositories. On Windows most Git commands now start as one process: VeriDone starts the `git.exe` in Git's own program directory, without a console. Each command used to take three processes: Git for Windows' `cmd\git.exe` launcher, a console host, and `git.exe`. A capture of a repository with no changes runs three fewer Git commands: seven in place of ten when it has a commit and no submodules. With 20 small repositories on a quiet Windows machine, the bootstrap's median went from 17.2 s to 7.9 s when the repositories have no changes, and from 18.8 s to 11.1 s when each has changes. Snapshots stay the same, so evidence bound before the upgrade stays bound.

### Fixed

- A check approved while its folder exists and VeriDone still cannot read the repository, as when its root is removed or waits for approval, is added once, and the answer is 201. It used to be written and answered with a 400, so a retry added it again.
- In the light theme, warning text such as the notice that a repository source is unavailable now meets the 4.5:1 contrast ratio.
- On a phone, the workspace explorer's tabs wrap, so each one can be reached without the dialog sliding sideways.
- A dialog takes its first focus only while focus is outside it, so keys typed into a field right after it opens stay in that field.
- The web app loads without a content security policy report. Its import of `@veridone/core` also brought in zod, which probes for eval when it builds its first object schema, so every page load reported a blocked eval and Firefox logged it as an error. The web app now imports `@veridone/core/scope`, which takes zod and the schemas out of the page and about 85 KB out of the JavaScript bundle. A Playwright check on the built page in Chromium, Firefox, and WebKit fails if a report or a console error appears while the page loads.
- The public demo no longer asks for an API it does not have. A build with `VITE_PUBLIC_DEMO=1` requested `/api/v1/bootstrap` when the page loaded and about every 15 seconds after that, GitHub Pages answered 404, and Chromium and WebKit logged each answer as a console error. That build now opens on the labeled synthetic data without that request or its timer. A build without the flag that has not reached its service still falls back to that data, says the service is unavailable, and keeps asking. Playwright checks both bundles in Chromium, Firefox, and WebKit.
- **View contract** works on the public demo and on a local page that has not reached its service. With no workspace to open the explorer on, the button showed nothing. It now opens the contract every workspace starts with, which the server seeds and the page shows from one definition in `@veridone/core`. Playwright opens it on the public demo's build in Chromium, Firefox, and WebKit, and at phone width in Chromium on a page without its service.
- A page that has reached its service says so when the service stops answering. It used to keep saying "Live local evidence" over data that was no longer being refreshed. A banner now names the time of the last data received, which stays on the page, and the inbox label, the navigation status, and the readiness line of the review carry that state. The buttons and links that start verdicts, check runs, exports, removals, and other changes are off until the service answers. A dialog already open stays open with its text and can still send, and the backup dialog and the workspace explorer take back their download links, since WebKit saved an empty file from them. A service that hangs counts as stopped after about 30 to 45 seconds, longer on a workspace that has answered slowly before, and the loading screen says so too when the first request gets no answer. A request that reaches no service now reads "The local service did not answer.", and a page holding the token of a service that has restarted is told to try again. Polling keeps one bootstrap request open at a time, so a slow workspace no longer piles them up. Under `pnpm dev`, a page waiting for its first answer stays on the loading screen; it used to show the synthetic demo as if the service were unavailable.
- A line break in a receipt's title, a verdict note, a reason, a source label, or any other fact except the claim no longer starts a new line in a Markdown packet, where it could pass for a second `- Verdict:` line. It shows as a space, or as an escape in a check's argument, and the JSON packet keeps the text as written.
- A Markdown packet shows the claim as a quotation, so a heading or a verdict an agent writes in it stays inside the quote.
- The restore preview shows its summary and the sentence after it on separate lines, and the receipt preview does the same for its closing notes.
- **Add source** says repositories and receipts must sit inside an approved root, and **Roots** says a restored root grants no read access until you approve it. They used to say VeriDone reads only approved roots and reads nothing under a restored one, which a pinned tool and a second root over the same path contradict.
- On a page with no workspace, such as the public demo, **Reject**, **Request changes**, and **Accept work** say the decision in the decision bar. Their only effect was the text of the evidence rail's last step, which sat off screen or under the bar at each size tested from 1280×720 down to 360×640, so a press seemed to do nothing. Playwright presses them on the public demo's build at those five sizes.
- **Show all reviews** clears the search as well as the filter. After a search that matched nothing it cleared only the filter, and the list stayed empty.
- The backup button at the foot of the navigation looks unavailable when it is: dimmed, with a not-allowed cursor, no hover highlight, and a tooltip saying it needs the local service. It used to look like the working theme button beside it.
- Each press of the theme button switches between light and dark. On a device set to dark, the third press went from dark to the system theme, which is also dark, and nothing changed. A press that lands on the device's theme still makes the page follow the device again.
- The review's **Decision readiness** section and the two columns below it fit the pane at desktop widths from 1002 px up. In windows 1002 to 1410 px wide, the branch, HEAD, scope, and worktree values beside the readiness score ran past the pane's right edge and the pane scrolled sideways, and up to 1446 px they ran into its right padding; in windows 1221 to 1250 px wide, the two columns below them did the same. The values now take a row of their own under the score where the pane cannot hold them beside it, and the two columns become one where it cannot hold both. Switching to another work item also widened the pane while the switch lasted and moved the decision bar off the bottom of the window, because the review slid in; it now fades in. Playwright checks in Chromium, Firefox, and WebKit that nothing in the review runs past its column at 360 px, 768 px, and nine desktop widths, and that in each frame of a switch with a review on screen, the pane and the page stay inside the window and the decision bar stays in place. While the service is not answering, it checks the review the same way at seven widths from 360 to 1920 px, and that the banner above it stays inside the window.
- On a phone, a check's long directory wraps inside its column in the workspace explorer, so the Checks tab no longer scrolls sideways. Playwright reaches each of the explorer's tabs where it is drawn at 320 px, 360 px, and 768 px, and at 320 px and 360 px while the service is not answering.
- Windows 861 to 1001 px wide show the inbox and the review one at a time, as a phone does. Side by side, the navigation, the inbox, and the review need 1002 px, so in that range up to 141 px of the review's right side sat past the window, and when the review took focus, the browser could slide all three columns left and take part or all of the navigation out of view. The decision buttons passed the window at 861 to 867 px, and the banner's text did while the service was not answering. Playwright checks the review and the inbox at 861, 900, 960, 1001, and 1002 px, with the service answering and not, in Chromium, Firefox, and WebKit.
- A work item title with no break opportunity breaks to fit the review and the inbox. It ran past both at every width and made each scroll sideways; on desktop widths it also covered or pushed away the review's status label. The layout checks give the second work item a 200-letter title with no break, which Playwright checks in the review and the inbox at all 16 widths, and while the service is not answering, in the inbox at 12 of them and in the review at 4, in the same three browsers.
- With the device set to reduce motion, the review pane, its criterion rows, the readiness bar, and the inbox rows now appear in place. They animate through Motion, which ignores that setting unless told, so the pane faded in, the rows faded and slid in, and the bar grew, as on any other device. Motion now sets each value at once while the device asks for reduced motion, as the stylesheet already did for CSS animation, and a change to the setting in an open page applies from the next animation. Playwright checks the public demo's build in Chromium, Firefox, and WebKit, with the setting on from the start and turned on in an open page.
- On Windows, a check or Git command that reaches its timeout or output cap, or is cancelled, ends even when `taskkill` fails. VeriDone ran `taskkill` once without reading its result and then waited for the process with no time limit, so the run, and the request waiting on it, could wait for as long as the process kept running. A failed `taskkill` is now tried twice more, and when those fail too, VeriDone tries to kill the direct process alone. On every system, a run returns with its timeout, cancellation, or output-cap state within two seconds after the kill, even when a process left behind still holds its output open; that process keeps running, and VeriDone stops reading its output.
- On Windows, VeriDone runs no `taskkill` on a check or Git command whose direct process has already exited. When the process had exited and a process it started kept its output open until the timeout, VeriDone ran `taskkill` on the old process id, which Windows may have given to another process by then.

## [1.2.0] - 2026-11-05

### Added

- **Checks** in the navigation lists each approved check with its pinned tool, arguments, and hash, and pins a tool again after the operator reviews it.
- Packets are signed with an Ed25519 key that the workspace creates on first use and leaves out of backups. **Download the packet signing key**, under backup and restore, saves the public key, and `pnpm verify:packet <packet.json> --key <public-key.pem>` checks that this key signed a packet. Packets written by VeriDone 1.1 and earlier still verify, as unsigned, and the verifier refuses a signing key of any other type.
- A check can name setup arguments that its pinned tool runs in the checkout before the check, with a ten-minute timeout, for example a frozen `pnpm install`. A setup that fails ends the run with its own exit code and output, files it writes outside ignored paths mark the evidence mutated, and a check without setup keeps its definition hash. Stored stdout and stderr each stay within the check's output limit in UTF-8 bytes, with the setup's part cut first.
- Restoring a backup first lists the roots, repositories, checks, and work items it would add, with the evidence and verdict counts, and writes nothing until the operator confirms; `POST /api/v1/workspace/preview` returns the same list.
- **Roots** in the workspace explorer lists each root with its state and approves a root restored from a backup.
- Packets name each check's command, setup command, working directory, and tool hash, and give the test counts from the last summary that node:test, Vitest, Jest, or pytest printed. A pytest summary that reports `157 subtests passed` is read with that part left out of the counts.
- **Replace** and **Retire** under **Checks** change a repository's policy. A definition stays fixed once approved, apart from pinning its tool again, so Replace opens the approval form filled in from the old check, then approves the new one and retires the old one in one step, and Retire takes a check out of the gate with a reason. The record and its evidence stay, packets show when it retired and why, and evidence counts only under the set of checks it ran with. A check that cannot be pinned, that needs a setup step in the clean checkout, or that was approved by mistake no longer holds the gate for good.
- The review shows what a check's latest run printed: **Show output** reads the end of each stream from `GET /api/v1/evidence/:id/output`. The bootstrap leaves output out, so polling no longer carries every run's output.
- The check dialog sets the timeout and the output limit, and **Manage checks** in the review opens **Checks**.

### Changed

- The check dialog suggests `node --test`, which runs in a clean checkout without installed dependencies.
- A declared scope of `./` means the whole repository and is stored as no scope.
- A work item's verdicts are listed by their place in the chain, so a packet heads its verdict history with the latest verdict whatever the clocks recorded.
- A repository capture skips `git submodule status` when the repository has no `.gitmodules` file; on Windows that script took about 1.7 seconds of every capture.
- Updated `motion` to 12.43.0, `lucide-react` to 1.59.0, `@hono/node-server` to 2.1.5, `@playwright/test` to 1.64.1, and `jsdom` to 30.1.3. jsdom 30, which the unit tests use, supports Node.js 22.22.2 or a later 22.x, 24.15 or a later 24.x, and 26 or later.
- Acceptance packets are schema version 2: identifiers are pseudonyms, a `checks` section and per-evidence `testCounts` are added, the payload hash covers keys in UTF-16 code-unit order (the RFC 8785 order), and the manifest carries the signature. Markdown and HTML render from one view of the JSON packet, so the HTML packet now carries the source, fingerprint, contract clauses, checks, and test counts as the Markdown packet does.
- The service computes each work item's readiness and sends it with the bootstrap, and the verdict gate and the review view use that one result. In the review score, the receipt of a degraded run counts as a failed gate.
- `packages/core` keeps the domain types, fingerprints, and declared-scope checks; the criterion, freshness, and triage evaluators and six schemas that only their own tests used are removed.

### Fixed

- A verdict is recorded on the work item the reviewer opened. The background refresh used to reset the selection to the first work item every 15 seconds, so a verdict written for one item could be recorded on another, and a local `?review=` deep link was lost on load.
- The verdict dialog names the work item, repository, commit, and fingerprint it records against.
- After the repository changes, an earlier verdict is marked superseded and the work item opens for a new decision. Accepting with every gate passing records a plain acceptance; the server stores an override reason only while required gates are open.
- Light-theme status, kicker, and diff text use a darker accent that meets WCAG AA contrast.
- A receipt whose time has no UTC offset, such as `2026-07-21 13:00:00`, imports as the machine's local time with an offset, and workspace export accepts receipts an earlier version stored that way. Receipt import and the workspace backup share one set of field rules, so a receipt that imports also exports; a time that is not a timestamp is refused at import.
- A receipt time with a UTC offset that stops at the minute, such as `2026-07-21T13:00Z`, still imports, exports, and restores: zod 4.5 and later require seconds, so VeriDone adds `:00`.
- The source dialog kept the previous discovery list while a new discovery ran, so a repository chosen from it could be replaced by the first repository of the new answer, and the dialog connected a repository other than the one chosen. Discovery now hides the previous list until it answers, drops an answer that a newer discovery replaced, and keeps a chosen repository that the new list still contains.
- The source dialog opens idle after an add closed it during a discovery; the button used to read "Discovering…" until it was pressed again.
- One approved root whose folder is gone stops nothing under the other roots. **Roots** marks it, and repositories under it report the reason in plain words.
- A verdict records while the repository cannot be read: a rejection, a change request, and an override bind to the last state captured, and a plain acceptance is refused with the reason.
- A backup restores up to 500 MB, up from 25 MB, and export refuses to write a larger one and names the data directory to copy. Evidence is never deleted, so a backup used to outgrow what restore read.
- An agent that writes each run's receipt to one file can import every run. The second used to fail with a database error, since a receipt's file path had to be unique.
- A backup carries what earlier versions stored and today's import refuses: a long run id, status, or task type, or a time that is no timestamp. One such record used to stop export altogether.
- Refusals say what to do next: a missing path, `VERIDONE_GIT` naming nothing, no approved root, more than 10,000 changed files, and a tool that cannot be pinned, which used to send the operator back to pin it.
- One check that refuses to start no longer keeps the review's other checks from running, and an empty workspace offers **Restore a backup** on its first screen.
- The built app loads every font subset from a file. Vite inlined the two smallest, Cyrillic Extended for Manrope and JetBrains Mono, as data URLs, which the content security policy blocks, so each page load logged two console errors and characters only those subsets cover fell back to another font. `pnpm smoke:built` now fails on an inlined font.

### Security

- A verdict is a compare-and-swap write. The verdict dialog keeps the repository fingerprint, claim hash, and latest verdict it showed when it opened; the server captures the repository again at decision time and records the verdict in one transaction only if all three still match, otherwise it answers 409 and says what changed. The dialog also refuses to submit once the workspace it shows has moved on. Each verdict records the claim hash it judged, and re-importing a receipt can no longer rewrite the claim of a work item that already has a verdict.
- Verdicts and evidence are append-only in the database itself: each work item's verdicts form a chain in which every verdict names the one it supersedes, SQLite accepts a new verdict only at the head of that chain, and it refuses any update or deletion of a verdict or evidence record, an insert that would replace one included. Workspace restore now adds what the workspace lacks: existing records stay as they are, evidence and verdicts with a known ID must match exactly, and each work item's verdicts replay in chain order through the same append path, so a backup can extend a history while recorded verdicts keep their content, and a verdict must judge the claim the local work item shows. A conflicting backup is refused as a whole. Restored evidence is marked imported and stays history without satisfying a gate, restored checks must have their tools pinned before they run, and their definition hashes are recomputed from the restored fields. Backups are written as schema version 2; version 1 backups still restore.
- Approving a check pins its tool. The executable resolves once to a canonical file outside the repository (a command name is searched on the absolute `PATH` entries; any other name must be an absolute path), and the file's SHA-256 becomes part of the check definition. Every run hashes the file again just before starting it and refuses to start if it changed, and hashes it once more after the run. **Pin tool again** under **Checks** shows the file and SHA-256 that would be pinned and pins only that file. A different file is a new definition, so evidence from the old tool stops satisfying the gate. Evidence records the tool path and SHA-256, and packets carry the hash. Checks approved before this change must be pinned before they run. A check's `PATH` keeps only absolute entries, and on Windows the programs it starts by name are not looked up in its working directory.
- Approved checks run in a checkout that VeriDone creates from the bound commit in its own temporary directory, so uncommitted changes, ignored files, build output, and Git configuration in the operator's repository cannot reach a check. Files are checked out as committed, without submodules or the operator's line-ending conversion, and a check that needs dependencies installs them itself. Checks refuse to start while the repository has uncommitted changes. After the run, VeriDone requires the checkout's HEAD to still be the bound commit and compares its work tree with a fresh index read from that commit, so a check that edits, commits, or hides a change in its checkout is recorded as mutated. Evidence recorded before this change no longer satisfies a gate. A SHA-256 repository gets a SHA-256 checkout.
- VeriDone starts Git by an absolute path found on the absolute `PATH` entries (or set with `VERIDONE_GIT`), from a directory outside every repository, and gives it a fixed configuration. System and global Git configuration are ignored except for settings that decide how files compare, such as line endings; a repository's fsmonitor hook, hooks, and external diff or textconv programs never run, every filter command its configuration names when VeriDone opens Git on it is blanked, and safe directories come only from the operator's own configuration. Git 2.32 or later is required.
- Updated `hono` to 4.13.13, `vite` to 8.1.6, `vitest` to 4.1.12, and `concurrently` to 10.0.6, and pinned patched transitive `undici`, `postcss`, `nanoid`, and `source-map-js`; `pnpm audit --audit-level low` reports no known vulnerabilities.
- Updated `zod` to 4.6.7 for GHSA-mrhx-c7xc-m3w5, in which validating an oversized constrained collection could exhaust memory.
- The API answers 403 to a request whose `Host` header, or the host of an absolute request URL, names anything other than its loopback names on its port or the host of an allowed origin. A web page that points its own domain name at 127.0.0.1 reads nothing from the API, the anti-CSRF token included.
- Redaction covers secret names that end an identifier, such as `NPM_TOKEN` and `AWS_SECRET_ACCESS_KEY`, quoted values that hold spaces, escaped quotes or escaped line breaks or lack their closing quote, values joined from adjacent quoted or escaped parts, as in `'alpha'"beta"`, the value after an option named for a secret, fine-grained GitHub, GitLab, Slack, and npm tokens, AWS key ids, JWTs, bearer values, and private key blocks, including one that the output cap cut off. Every text in a packet passes through these rules, a restored contract's included, and also loses quoted paths up to their closing quote, Windows paths written with forward slashes or escaped as in JSON, paths whose folders hold spaces, UNC paths, home-relative paths, and paths under `/mnt`, `/srv`, `/root`, `/Volumes`, `/private`, and `/media`. Each pattern takes linear time on hostile check output.
- Packets redact the local paths the workspace knows: its home and temporary directories, approved roots, pinned tools, repositories, and pending roots. A known path matches wherever a text names it, right after a command-line flag or a local URL's host included, and in these forms: either separator, JSON escapes, quotes, file URLs with percent-encoding in either case, a shell's backslash escapes, a POSIX shell's name for a Windows drive, `~` or `$HOME` for a path under home, and the other name the system gives the home or temporary directory, such as a Windows short name or macOS's `/var`. Known paths go before credentials, so an assignment that holds one keeps none of it, and what follows a known path inside it goes with it, read as Windows or a POSIX shell reads a path, by how the path's root is written, the rest of a last segment the text goes on in, as in `project copy/x`, included. A known path is redacted whole when a folder name in it holds a space, and a POSIX path outside the listed prefixes, such as `/work/clients/acme`, is redacted when an approved root holds it. Every string in a packet's payload passes through the sanitizer, the evidence fields that a restored backup can set included, and a Windows path ends at `;`, so each entry of a PATH list is redacted. A packet text longer than a million characters appears as `[REDACTED: text too long to sanitize]`.
- Redacting check output finishes on any text up to the largest output limit, ten million bytes. One long credential value, token, or bearer value used to throw, from about 5.6 million characters, so the run's evidence was never recorded, and the JWT pattern took quadratic time on `eyJ-eyJ-…`, 14 minutes at the default limit of one million bytes on the thread that serves requests. Every text the old patterns could read gets the same output.
- Exporting a packet finishes on any check output up to the largest output limit, on both streams. One long line in a text that holds a character past Latin-1 used to throw in the test summary, from about 8.4 million characters, so the export answered 400. The summary's patterns now read no line past 65,536 characters, color codes aside, so they skip pytest's summary line when a `COLUMNS` setting pads it past that length.
- Packets carry the repository id, fingerprint, worktree hash, claim hash, check-definition hashes, and artifact hashes as HMAC-SHA256 pseudonyms under a workspace key that backups leave out. The repository id hashes the local path and the others take local data as inputs, so each raw value would let a reader confirm a guessed path or file.
- A root restored from a backup stays pending until the operator approves it: discovery refuses it, and nothing under it counts as approved. Approval resolves the path again and refuses one that is missing or now resolves somewhere else.
- Accepting a work item whose receipt reports a failed or incomplete stage requires an override reason; the server used to record such an acceptance as a plain one. The receipt is found by its exact run id.

### Documentation

- Workspace checksums are described as unsigned integrity checks; verdict history, fingerprint coverage, and the default contract are described as implemented; `docs/ACCEPTANCE.md` maps each criterion to its test or manual evidence.
- The architecture, security model, data formats, installation notes, and user guide describe the clean checkout, tool pinning, Git invocation, compare-and-swap verdicts, and append-only restore, with the limits of each; `docs/ACCEPTANCE.md` adds VER-07 to VER-09, DEC-04, and EXP-05 with their tests.
- The README, security model, architecture, data formats, and user guide describe the Host allowlist, redaction, pseudonyms, packet signatures and what they prove, the restore preview, pending roots, setup steps, and server-computed readiness; `docs/ACCEPTANCE.md` adds ONB-07 and VER-10 with their tests.
